# Comparison protocol (Version 1 vs Version 2)

- **Version 1:** one ChatGPT chat does all five stages alone. It is scored on accuracy only. It cannot earn an official Design or Finish lock.
- **Version 2:** this design, the parent plus seven child bots (the Stakeholder only in Stages 1–2). It seeks an official lock under these gates and is described as a same-family role split.

## Fairness
Both versions get the same case pack, rules, locked questions, and stopping rules. Neither sees the other's work or the key. The case must be fresh to both.

**Open for the owner (live Stakeholder).** Version 2 now settles Stages 1–2 in a live chat with a Stakeholder bot and the owner; Version 1 gets the written brief only. Owner answers and twists given in the Version 2 chat are inputs Version 1 did not get. Until the owner decides how to even this out (for example, give Version 1 the same captured owner messages), a Version 1 vs Version 2 score must say this.

## Scoring
Scoring happens only after both versions are sealed. The earlier key preparer from the ChatGPT (Version 1) side holds the private key and scores both versions blind. That scorer is not a live role. Live roles never see the key. The scorecard is written in advance:
1. Accuracy on four dimensions: target/population; numbers and memberships (money to the cent, percents to 2 decimals); interpretation and claim ceiling; action and rationale.
2. Error list, with error types and whether they are shared.
3. Wall-clock time and operator hands-on time.
4. Usage and cost.

No winner is declared mid-run. Report limits plainly: one case is not a general accuracy claim.

## Run cap
- One attempt per version on Case B.
- A maximum of 3 repair rounds.
- Stop and report after about a day of work per side.
- If a side is blocked (for example by a limit or an outage), wait and retry up to 3 times, then report.
