# Gate list

Every gate returns PASS, FAIL (analysis defect), or TOOL_ERROR. An unrun gate is not PASS. No verbal waiver. All gates are run by the Gate Runner; the Database Connector executes the SQL inside G3S; the Coordinator advances only on a PASS for the attempt it requested.

G3S and G3K are Stage 3 gates and must PASS before G3 locks the design. G3K is Python, run by the Gate Runner. ID mapping from earlier drafts: former G4a (SQL source gates) is now G3S; former G4b (fixtures) is now G4a; former G4c (reconciliation) is now G4b; G4c is the new post-reconciliation review; G4d remains the release gate.

**Python gates are run by the Gate Runner.** Each needs a parity test against the existing R gate before use. Status (2026-11-10): G0, G1, G2, G2F, G3S (sqlite engine), G3K, G3, G4a, G4b, G4c, G4d, G5, G6 and GP are **implemented and tested**, and so are GD and the repair cap. G1, G2, G3, G4d and G5 include the ported R stage checks, and G4d includes the whole ported R Workflow Gate. Those ports pass R-vs-Python parity on the R repo's own test suites and on the gate fixtures. G6 requires the R `finalize` certificate and re-checks its hashes. G0 has no R counterpart. See [../gates/README.md](../gates/README.md).

**Live Stakeholder (Stages 1–2).** The capture tool is `python3 -m gates.stakeholder` (init, capture, statement, lock). The Stakeholder never approves a lock; see docs/rules.md 31–36.

**Attempts.** Every gate run has an attempt id and its outcome (PASS, FAIL or TOOL_ERROR) is recorded once under `artifacts/gates/attempts/`; a TOOL_ERROR also becomes the current record. The Coordinator advances only when `python3 -m gates.attempt <GATE> <root> <id>` exits 0 for the attempt it requested.

**Finish order.** owner approves the exact finish package -> R `complete finish` -> G5 -> R `finalize` -> G6. G5 reads the R finish receipt, which needs the owner's approval of the exact package. G5 and G6 enforce this order from the recorded times (repair round 2): G5 needs the exact-package owner approval and R finish completion no earlier than that approval; G6 needs approval <= R finish completion <= G5 <= R finalization.

**Review coverage.** A review counts only if the reviewer received every current subject whole, at the same path, with the current hash.

**Repair cap.** Three unsuccessful repairs on the same defect, then escalate. Changing author does not reset the count.

**Finding classes (Risk Reviewer).** `must fix` requires a revision; `advisory` does not block the gate by itself.

## Closing a stage

`python3 -m gates.close <closing gate> <root>` (gates/close.py) is the only way a stage is called closed. It reads the recorded verdicts and exits 0 only if the closing gate, every gate it depends on and G0 are PASS with inputs still current, and no packet is sent but unanswered or captured but not promoted. A FAIL record, a missing record or a changed input exits 1. Closing gates: Stage 1 G1, Stage 2 G2, Stage 2F G2F, Stage 3 G3, Stage 4 G4d, Stage 5 G5 then G6. Each verdict is also written once under `artifacts/gates/close/`.
